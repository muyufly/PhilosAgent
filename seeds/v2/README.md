# 分层哲学初始化 v2

定位更新：这组内容保留为方法资源与层级消融对照。关于具有内在论证关系、能在经历中修正的哲学系统，见[系统原型](../systems/README.md)及[方案 v0.0.5](../../planv0.0.5.md)。八条分层原则本身不等于已实现这样的系统。

这版保留抽象哲学，同时给 Agent 可直接采用的方法约束。它是待验证的研究资源，不是已经证实有效的提示方案，也不代表完整重建某一哲学体系。

每个完整种子仍使用现有 `schema_version: 1` 和 `items: list[str]`，没有更换存储结构、增加学习器或规定生成工具的具体算法。目录名 v2 表示内容版本。八条初始原则分为三层：

| 层 | 条目 | 作用 | 批判理性组示例 |
|---|---|---|---|
| W：世界观与认识前提 | W1–W2 | 如何理解对象、知识、变化与错误 | 对象独立于偏好；认识可错，知识通过批评增长 |
| T：方法论 | 正文标记 M1–M2 | 上述立场如何组织分析、选择和检验 | 比较竞争猜想，优先区分性检验，审查反驳及辅助条件 |
| A：行动约束 | A1–A4 | 何时行动、做什么、如何检查、何时停止或修订 | 指明改变判断的证据，寻找反例，区分工具失败与有效反驳 |

正文的 M1/M2 是方法条目 ID；实验方案以 T 表示方法层，M 专指普通任务经验，避免同符号混用。A 指向对应 M，M 指向对应 W，构成可读的来源关系。当前运行时只将这些条目作为同一 Φ 提供给模型，**没有结构化依赖解析或分层更新机制**。能否实际利用这些关系由后续实验检查。

## 三组完整种子

- [engineering.json](engineering.json)：以目标、现实约束、系统依赖和有限资源为认识前提；方法侧重任务契约、分解核对、局部诊断和条件复用。作为认真编写的通用工程对照。
- [dialectical.json](dialectical.json)：强调客观条件、联系、过程及认识与实践的往复；方法侧重具体关系、主要制约、阶段变化和条件化重组。本项目采用这一有限的辩证方法译解，不声称覆盖所有辩证法传统。
- [critical.json](critical.json)：采用实在与可错认识的前提，以及批评推动知识增长的取向；方法侧重竞争猜想、区分性检验、错误消除和反对事后免疫。不将一次失败机械等同于证伪全部解释。

三组均避免强制长计划、制造矛盾或假想解释；都允许简单任务直接作答、证据不足时保留不确定性、停止无收益的检验。三层均是题间可修订状态，不把 W 设成永远不可更改的系统命令，也不要求每轮必须修订。八条是初始化格式，不是演化后必须维持的条数。

行动约束包含对记忆的**语义要求**，例如保留适用条件、来源和反例。它们未规定字段、数据结构、检索公式或存储实现；因此仍由原生 MemEvolve 提出代码。报告应称其为“哲学启发的方法及记忆设计先验”，不能把提示中已写出的行为要求描述为 Agent 无提示发明了新机制。

## 批判理性组的层级消融

首轮预先选批判理性组，是因为“区分性检验和反例”较容易定义可观测行为；不是因为它在旧四题中得分较高。准备两个与完整版本接近字符长度的对照：

- [critical-abstract-matched.json](ablations/critical-abstract-matched.json)：W+T，仅保留抽象认识前提与方法论，八条。
- [critical-operational-matched.json](ablations/critical-operational-matched.json)：A-only，只保留相同主题的操作规则，八条，无未展示的 W/M 引用。

这两包是重新编排的等长度近似版本，**不是从完整版删去几条后的同文本消融**。字符长度不等于模型 tokens；正式冻结前需以锁定模型的 tokenizer 或可核验 usage 校准，最长与最短的实际 seed tokens 比值须不超过 1.10。无法校准时报告为近似长度匹配，不宣称严格控制 token。不得通过重复空话凑长度。

若首轮有信号，再从 `critical.json` 原样取前四条或后四条做删层配对；A-only 仅去掉“落实 M1/M2”来源标签，正文不改。这项配对固定层内文本但长度不同，应与等长度实验合看，不能单独证明世界观有独立效果。

## 初始化与修改

在仓库根目录的 PowerShell 执行以下命令，只创建隔离运行，**不调用模型**：

```powershell
.\.venv\Scripts\python.exe -m philoagent init critical-v2-draft --seed critical --seed-file seeds/v2/critical.json
```

该示例未提供开发集，因此只用于检查初始化。正式任务运行前，应以新的运行名称和 `--data <已冻结的开发集JSONL路径>` 创建运行；留出集不能传给 `--data`。`--seed` 是类别标签，`--seed-file` 决定实际文本，二者应正确对应。

自定义源文件的原始字节存为新运行的 `seed_source.json`，路径及 SHA-256 写入 `run.json.seed_source`，实际 Φ 进入 `lineage/lightweight_memory/orientation.json`。随后修改源文件不会重写已建谱系。不要直接改旧谱系；候选仍通过 `orientation_items` 继承、替换或清空。

不加 `--seed-file` 仍读取原来的 `seeds/*.json`。`--seed none` 表示空 Φ，不能同时指定文件；它仍保留原生冷启动记忆。旧消融执行器尚不接受本目录的层级矩阵，应使用新方案指定的后续评测适配，不要通过手改旧 manifest 切换种子。
